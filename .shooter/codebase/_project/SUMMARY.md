## Architecture

- **Pattern:** Modular plugin with command dispatch, core logic, UI, and tmux integration layers
- **Entry point:** `lua/shooter/init.lua` → `setup()` → registers commands, keymaps, syntax
- **Command dispatch:** `lua/shooter/commands.lua` routes all `Shooter*` commands to handlers
- **Core logic:** `lua/shooter/core/` — shot detection (`shots.lua`), manipulation (`shot_actions.lua`), files (`files.lua`)
- **Tmux layer:** `lua/shooter/tmux/` — pane creation, text sending, AI process detection
- **UI layer:** `lua/shooter/telescope/` — pickers for files, shots, queues
- **State:** `lua/shooter/session/` — per-repo session persistence (filters, sort, vim mode) as JSON

**Data flow:** User command → `commands.lua` → core module → buffer manipulation → tmux send → AI pane

See ARCHITECTURE.md for full details.

## Concerns

**HIGH:**
- Shell injection risk in path concatenation — multiple `io.popen()` calls with unescaped paths (`inbox/init.lua`, `repos.lua`, `helpers.lua`, `data.lua`, `project.lua`)

**MEDIUM:**
- Unchecked shell command failures — stderr silenced with `2>/dev/null`, no exit code checking
- Missing error handling in file I/O — partial writes undetected
- Fragile timestamp-based response viewer lookups — depends on `@ref` or header timestamp parsing
- Tight tmux coupling — no graceful degradation without tmux
- vim-i3wm-tmux-navigator dependency — niche plugin marked as required
- External script paths not validated — hardcoded `~/dev/scripts` in `wrapper.lua`
- Untested critical paths — no tests for shell injection, config merging, special chars in tmux

See CONCERNS.md for full details.
