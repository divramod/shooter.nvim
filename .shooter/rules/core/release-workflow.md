# Release Workflow

Version lifecycle, changelog generation, and multi-CLI distribution.

## Version Lifecycle

| Bump | Who | When | Example |
|------|-----|------|---------|
| Patch | AI (per-commit) or Human (release) | Every commit or small releases | `0.0.61` → `0.0.62` |
| Minor | Human only | Release (new features, accumulated changes) | `0.0.62` → `0.1.0` |
| Major | Human only | Breaking changes | `0.1.0` → `1.0.0` |

AI agents bump patch per-commit automatically. Human releases can be patch (default), minor, or major via `sho:prj-release`.

## Release Process

Human runs `/sho:prj-release` which:

1. Previews the version change and changelog entry (dry-run)
2. Asks for confirmation
3. Bumps `.shooter/VERSION` (patch by default, minor or major if requested)
4. Syncs version to `package.json`, `Cargo.toml`, `pyproject.toml` (if present)
5. Generates CHANGELOG entry from conventional commits since last tag
6. Commits: `chore(release): vX.Y.Z`
7. Tags: `vX.Y.Z`
8. Pushes with tags

## Release Checklist

Before creating a release, ensure:

- All tests pass
- Build succeeds
- No in-progress beads (`bd list --status=in_progress` is empty)
- No uncommitted changes (`git status` is clean)
- Main branch is up to date with remote
- Cross-CLI verification passes (`sho_dist-verify.sh` — automated by release script)

## CHANGELOG Format

Uses [Keep a Changelog](https://keepachangelog.com/) with sections mapped from conventional commits:

| Commit Type | Changelog Section |
|-------------|-------------------|
| `feat` | Added |
| `fix` | Fixed |
| `refactor`, `perf` | Changed |
| `docs` | Documentation |
| `chore`, `ci`, `style`, `test` | Other |

## Update Distribution

`sho:self-distribute-to-clis` distributes to ALL installed CLIs simultaneously:

- Claude (`~/.claude/`)
- Gemini (`~/.gemini/`)
- OpenCode (`~/.config/opencode/`)
- Codex (`~/.codex/`)
- Kimi (`~/.kimi/`)
- Antigravity (`~/.antigravity/`)

All agents get identical instructions. No per-CLI selection — prevents version skew. OpenCode uses a different format (YAML object tools, flat command dir) which is handled by converter scripts at distribution time.

After distribution, `sho_dist-verify.sh` confirms all 4 major CLIs have the correct artifact count, version, and format. Agent files (CLAUDE.md, AGENTS.md, GEMINI.md) are regenerated in all shooter-enabled projects.

## Install

New users install via:
```bash
curl -fsSL https://raw.githubusercontent.com/divramod/shooter/main/ai/scripts/shell/sho_dist-install.sh | bash
```

This auto-installs all 4 major CLIs, clones shooter, distributes, and verifies.

## Online Update

`sho:self-update` pulls the latest from GitHub, distributes to all CLIs, and verifies:
```
/sho:self-update
```

## Bead Aggregation in Releases

Release commits should aggregate all `Beads:` trailers from commits since the last tag. The release script collects all bead IDs referenced in `Beads:` trailers between the previous tag and HEAD, deduplicates them, and includes a single `Beads:` trailer in the release commit with the full list. This provides a complete audit trail of which beads were addressed in each release.

## Rules for AI Agents

- **Never create releases** — releases are human decisions via `sho:prj-release`
- **Continue using patch bumps** for regular work commits
- **Write clear commit subjects** — they become the changelog entries
- **Follow conventional commit format** — the changelog generator depends on it
- **Do not modify CHANGELOG.md directly** — it is generated by `sho_release-changelog.sh`
- **Do not create git tags** — tags are created by `sho_release-create.sh`
